## 이 step의 목적

> 숨긴 `log --follow` 가 늦게 커밋된 행을 건너뛰지 않게 최근 id 구간을 다시 읽는다. 출력 줄이 id 순서에서 조금 뒤섞일 수 있다.

## 지금 동작

- IDENTITY id 는 커밋이 아니라 **INSERT 할 때** 정해진다.
- 그래서 A 가 id 1 을 받고 아직 커밋하지 않은 사이 B 가 id 2 를 받아 커밋할 수 있다.
- 그러면 `--follow` 는 2를 찍고 `last=2` 가 된다. 뒤에 A 가 커밋해도 `id > 2` 만 묻기 때문에 1은 영영 찍히지 않는다.

## 작업

### 1. 테스트 먼저 (`tests/test_cli.py`, DB 필요)

`_follow` 를 직접 부른다. 무한 루프를 멈추게 하는 방법은 다음과 같다.

- `monkeypatch.setattr(cli.time, "sleep", fake_sleep)` 로 바꾼다.
- `fake_sleep` 은 호출 순서에 따라 정해 둔 일을 하고, 마지막 호출에서 테스트 전용 예외를 낸다. 그 예외는 `pytest.raises` 로 받는다.
- 실제로 기다리지 않는다.

**늦은 커밋 (새 동작)**
1. 커넥션 A(`psycopg.connect(pg_dsn, row_factory=dict_row)`, 자동 커밋 아님)로 `audit.write(cur, "a", [audit.process_add("late_one")])` 를 한다. **커밋하지 않는다.** id 1을 받는다.
2. `_follow(AuditRepository(db), [], False, "", "", "", "")` 를 시작한다. `latest_id()` 는 커밋된 것만 보므로 0 이다.
3. sleep 1회차: 다른 커넥션으로 `process_add("early_one")` 을 쓰고 커밋한다(id 2).
4. sleep 2회차: A 를 커밋한다.
5. sleep 3·4회차: 아무것도 하지 않는다(다시 찍지 않는지 보려는 것).
6. sleep 5회차: 멈춘다.

`capsys` 의 stdout 에 대해 단언한다.
- `"early_one"` 이 정확히 한 번 나온다.
- `"late_one"` 이 정확히 한 번 나온다.

**수정 전에는 `late_one` 이 0번이라 실패해야 한다.**

**회귀**
- `seen` 으로 넘긴 줄(이미 `log` 가 찍은 줄)은 `_follow` 가 다시 찍지 않는다.
- 새 줄이 없으면 아무것도 찍지 않는다.

A 커넥션은 `finally` 에서 닫는다(롤백이든 커밋이든). 열린 채 두면 `pg_dsn` fixture 의 DROP DATABASE 가 막힌다.

### 2. 구현 (`src/genviewer/cli.py` `_follow`)

- 다시 물을 때 `after_id` 를 마지막으로 찍은 id 가 아니라 **그보다 일정 구간 앞**(예: `last - _FOLLOW_WINDOW`, 0 아래로는 가지 않음)으로 둔다.
- 이미 찍은 id 는 집합으로 기억해 다시 찍지 않는다.
- 이미 찍은 id 에는 처음 `seen` 으로 받은 줄의 id 도 넣는다.
- 집합은 구간 아래로 내려간 id 를 버려 크기를 묶어 둔다.
- 구간 크기는 상수로 두고 이유를 주석으로 적는다. 그 구간보다 더 늦게 커밋된 줄은 여전히 건너뛸 수 있다는 것도 적는다.
- 한 번에 따라잡는 최대 줄 수(`_FOLLOW_CATCHUP`)의 뜻은 그대로다.
- `AuditRepository.recent` 의 계약(조건에 맞는 마지막 limit 줄, id 오름차순)은 바꾸지 않는다. 필요하면 쓰기만 한다.
- 불변식
  - 한 줄은 많아야 한 번 찍힌다.
  - 구간 안에서 늦게 커밋된 줄은 한 번 찍힌다.
  - 필터(`--who`, `--process`, `--device`, `--find`)와 `--detail` 은 지금처럼 적용된다.
  - 기억하는 id 수가 끝없이 늘지 않는다.

### 3. 변이 검사

- `after_id` 를 다시 `last` 로 두면 "늦은 커밋" 테스트가 실패하는지 본다.
- 찍은 id 집합 검사를 빼면 "정확히 한 번" 이 실패하는지 본다.
- 둘 다 손으로 되돌린다.

1. 위 AC 커맨드를 실행한다. `GENDB_TEST_PG_DSN` 이 없으면 아무것도 고치지 말고 blocked 로 끝낸다.
2. 아키텍처 체크리스트를 확인한다.

   - 테스트가 실제로 기다리지 않는다(`time.sleep` 을 바꿔 끼웠다).
   - 열어 둔 커넥션을 닫는다.
3. 결과에 따라 `phases/7-service-fixes/index.json` 의 step 4를 업데이트한다.
   - 성공 → `"status": "completed"`, `"summary": "cli._follow: after_id 를 last-<구간> 으로, 찍은 id 집합(구간 밖은 버림)으로 중복 방지. 처음 실패한 테스트: <이름과 단언>. 변이: <결과>. README 변경 이력 한 문장. DB 테스트: <N passed>"`

## 금지사항

- LISTEN/NOTIFY, 트리거, `xmin`·`pg_snapshot` 같은 새 장치를 들이지 마라. 이유: 승인된 방법은 "최근 id 구간을 다시 읽는다" 다. 서버 쪽에 손대지 않는다(ADR-005).
- `--follow` 가 아닌 `log` 의 출력·필터·종료 코드를 바꾸지 마라. 이유: 승인 범위 밖이다.
- 늦은 줄을 기다리려고 출력을 늦추거나 정렬해 내지 마라. 이유: 승인된 것은 "조금 뒤섞일 수 있다" 이고, 따라 보기가 늦어진다.
- 기존 테스트를 깨뜨리지 마라.
